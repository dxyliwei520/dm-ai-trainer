## 十、桌面小工具：GPU 显存 / 内存监控（2026-11-09 新增）

| 项 | 值 |
|---|---|
| 桌面快捷方式 | `C:\Users\liwei\Desktop\GPU占用监控.lnk` → `wscript.exe` + 下面的 .vbs（**无控制台闪窗**） |
| 启动器 | `E:\ai-train\tools\gpu-monitor.vbs` |
| 主程序 | `E:\ai-train\tools\gpu-monitor.ps1`（WPF 单文件，**纯 ASCII**，零第三方依赖） |
| 预览图 | `E:\ai-train\tools\preview.png` |

**界面**：VRAM 进度条（≥90% 转红）+ RAM 进度条 + 底部 `GPU 利用率 / 温度 / poll 1.5s`。
窗口置顶、可拖动；点右上 ✕ 或按 **Esc** 退出，**关掉窗口即结束进程**（无后台残留）。

**开销（训练中实测）**：
- 进程内直接调 `nvml.dll`（P/Invoke），**不 spawn nvidia-smi、不占 GPU、不碰训练进程**
- 稳态 **10 秒 16 ms CPU ≈ 0.16% 单核**；内存 ~124 MB
- 实测同一时段训练 `step 477 → 494`（2.95 s/it）正常推进，loss 0.27 → 0.22

**自检方式**（不需要开窗口，渲染一张图就退出）：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File E:\ai-train\tools\gpu-monitor.ps1 -Snapshot
# → %TEMP%\gpu-monitor.png
```

**排错**：若 VRAM 行显示 `NVML unavailable` → 显卡驱动缺 `C:\Windows\System32\nvml.dll`。
**未做**：开机自启（要的话再加计划任务，需用户确认）。

## 十一、Qwen-Image-2.1 图片编辑训练台（8198，2026-11-09 新增）

**现已不只是 H3 台了**：同一套工作区里还多了一个**图片编辑 LoRA 训练台**，端口 **8198**，
后端是 **ai-toolkit**（不是 musubi —— musubi 不支持 2.1）。

| 项 | 值 |
|---|---|
| 启动 | 双击 `E:\ai-train\_START_WEBUI_QWEN.bat`（会自动开浏览器；关窗口=停服务） |
| 网址 | `http://127.0.0.1:8198`（页面与接口同一个进程） |
| 使用说明 | **[docs\07-Qwen训练台-使用说明.md](07-Qwen训练台-使用说明.md)** |
| 技术细节 + 4 个新坑 | **[docs\06-Qwen图片编辑训练台.md](06-Qwen图片编辑训练台.md)** |
| 素材 | `datasets\qwen_*\{control,target}`，caption = `target` 里同名 `.txt` |
| 产物 | `runs\qwen_*\`（点网页「装进 ComfyUI」自动拷到 loras） |

**要不要下 30 GB？不要** —— F 盘 ComfyUI 的 2.1 三件套直接用，只需把几 MB 配置预下载进 HF 缓存
（已在 `~\.cache\huggingface\hub\models--Qwen--Qwen-Image-2.1\`）。
**实测**：512×512 = 2.4 秒/步；加载模型 2~4 分钟；显存峰值 ~12 GB；40 步能出 76 MB LoRA 与有效样张。
**边界**：两个台子可以同时开着，但**不能同时训练**（一块 16 GB 显卡）。
